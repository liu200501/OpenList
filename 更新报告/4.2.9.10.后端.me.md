## 二、议题详情（后端）

### 1. 可配置的独立代理

**背景**：报错 `failed get objs: failed to list objs: Share Unavailable in Your Region` 属于 **PikPak 分享 API 的区域封锁**，与下载链路无关。已验证：

- 带 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:10808` 的进程可正常列目录，不带则失败；
- 10808 端口由 v2rayN 监听，`Invoke-WebRequest -Proxy http://127.0.0.1:10808 http://www.google.com` 返回 200；
- 原有 `down_proxy_url` / `web_proxy` / `webdav_policy` / `proxy_range` 都只作用于**下载字节**阶段，覆盖不到 API/列目录。

**方案**：拆成两个正交能力——

**① 通用存储级下载代理 `download_proxy_url`（所有网盘）**

- 新增到 [internal/model/storage.go](../internal/model/storage.go) 的 `Proxy` 结构，经 [internal/op/driver.go](../internal/op/driver.go) 暴露为通用配置项；
- 在 [internal/op/fs.go](../internal/op/fs.go) 的 `Link()` 中注入到 [internal/model/args.go](../internal/model/args.go) 的 `Link.DownloadProxyURL`（`json:"-"`，不下发前端，`Clone()` 一并复制）；
- 通过 context 贯穿下载链路：[internal/stream/util.go](../internal/stream/util.go) 的 `withDownloadProxy`、[server/common/proxy.go](../server/common/proxy.go) 的透明代理与 `ProxyRange`、[internal/net/serve.go](../internal/net/serve.go) 的 `HttpClientForContext(ctx)`（按代理地址缓存 client，套用 `safeTransport` 保留 SSRF 防护）；
- 强制服务端代理模式：[server/common/check.go](../server/common/check.go) 的 `ShouldProxy`、[server/handles/down.go](../server/handles/down.go) 的 `canProxy`，以及 `Webdav302()` / `WebdavProxyURL()` 在配置了下载代理时返回 `false`——302 是浏览器直连，服务端无法为其套代理。

**② PikPak 专属 API 代理 `api_proxy`**

- 在 [drivers/pikpak/meta.go](../drivers/pikpak/meta.go) 与 [drivers/pikpak_share/meta.go](../drivers/pikpak_share/meta.go) 新增 Addition 字段；
- [drivers/pikpak/util.go](../drivers/pikpak/util.go) 与 [drivers/pikpak_share/util.go](../drivers/pikpak_share/util.go) 增加 `restyClient()`，让 `request()` / `login()` / `refreshToken()` 走独立客户端；为空时回退全局 `base.RestyClient`，兼容全局代理与替换全局 client 的测试；
- 客户端缓存随 Init 重建，编辑存储改代理后自动生效；
- 底层能力 [drivers/base/client.go](../drivers/base/client.go) 的 `NewRestyClientWithProxy`：空代理返回 `nil, nil`，校验 `http/https/socks5/socks5h` scheme。

**补充说明**：全局 `proxy_address` 只在配置文件 `config.json` 或 `PROXY_ADDRESS` 环境变量里设置，Web「设置 > 全局」页面没有这个字段——这是用户当时找不到它的原因。

### 2. PikPak 分享免账号下载（仅调查，未修改）

**结论**：PikPak 分享链路不依赖账号，靠三样东西即可工作：匿名 captcha token、由分享密码派生的 share pass code token、公开分享 API（列目录、取链接）。拿到分享链接 + 提取码即可下载，无需登录账号。**按要求未做任何修改**；[drivers/pikpak_share](../drivers/pikpak_share) 本次仅为 API 代理增加 `api_proxy`，不涉及免账号逻辑。

### 3. 上传 `temp` 丢失

- **仅浏览器意外关闭**：Web PUT「添加为任务」时请求体在 handler 返回前已同步缓存到服务端，任务管理器仍存活，可一键重试；
- **电脑/服务意外重启**：任务管理器与临时缓存都在进程内存中，不持久化，重启后无法恢复。

处理：上传持久化能力（请求体同步落盘 `prepareUploadStream`、`UploadTask.Run()` 的 `Rewind()` 回绕、`KeepStreamKey` 保护缓存、crypt 密文落盘缓存）此前已实现于 [internal/fs/put.go](../internal/fs/put.go) 与 [drivers/crypt/cipher_cache.go](../drivers/crypt/cipher_cache.go)，本次**审查确认正确后复用**，未重复实现。后端通用任务路由早已注册 `/task/upload/retry` 等接口（[server/handles/task.go](../server/handles/task.go)）；本次前端才把重试按钮开关打开。

**已知限制**：机器重启场景若要真正"一键重试"，需要把任务元数据 + 完整服务端缓存一并持久化，当前未做。WebDAV PUT 是同步 `PutDirectly`，不走任务系统，只有配合本地有源文件的外链同步工具才有意义。

### 4. 密文复制（后端部分）

- [server/handles/fsread.go](../server/handles/fsread.go) 的 `ObjResp` 新增 `EncryptedName string \`json:"encrypted_name,omitempty"\``；
- `toObjsResp` 增加可变参数 `includeCipherName ...bool`，仅在 `provider == "Crypt"` 时填充：先 `model.UnwrapObjName(obj)` 拿到底层对象，跳过 `Virtual` 掩码，取 `stdpath.Base(rawObj.GetPath())`；
- 只下发**密文 basename**，不下发完整密文路径，避免泄露底层目录结构；`FsList` 与 `FsGet` 的 Related 两处调用点均已更新；
- 配套的 `image_preload_count` 设置在 [internal/bootstrap/data/setting.go](../internal/bootstrap/data/setting.go) 注册（`TypeNumber`，PREVIEW 组，默认 2），设置页自动渲染为数字输入框。前端按钮与预加载读取见前端报告。

### 5. 压缩包内图片预览慢（后端部分）

| 根因 | 后端修复 |
|------|----------|
| `InternalExtract` 每次请求都重新打开底层存储、重新解析压缩包并解压成员，且无缓存 | 新增 [internal/op/extract_cache.go](../internal/op/extract_cache.go)：把成员完整解压到 `TempDir` 临时文件，命中直接打开；`singleflight` 合并并发解压；TTL 10 分钟 + 512 MiB 容量上限（按最旧淘汰）+ 后台定时清理；[internal/op/archive.go](../internal/op/archive.go) 的 `InternalExtract` 改用该缓存，并对缓存文件被外部删除做了失效重建兜底 |
| 随机读取用 `Range{Start: off, Length: -1}`（一直读到 EOF），crypt + 移动云盘链路上反复拉取整个压缩包 | [internal/stream/stream.go](../internal/stream/stream.go) 的 `getReaderAtOffset(off, minLen)` 改为有界长度，钳制到 `conf.MaxBlockLimit`，同时保证单次 `ReadAt(p)` 即使大于上限也能被满足（避免误报 EOF） |

配套地，[server/handles/archive.go](../server/handles/archive.go) 的 `proxyInternalExtract` 响应从 `no-store` 改为 `public, max-age=600`，并基于稳定身份（URL Path + `inner`/`pass` + 文件名 + 大小，刻意不含带时间戳的 `sign`）生成 ETag，支持 304。前端预加载优化见前端报告。
