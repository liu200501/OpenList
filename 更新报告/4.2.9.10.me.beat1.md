## 二、议题详情（后端）

### 1. 索引不自动更新的根因修复

排查后发现并非单一原因，而是一组相互叠加的问题：

**① 索引进度「伪完成」**

`index_progress` 里长期存着：

```json
{"obj_count":0,"is_done":true,"last_done_time":null,"error":""}
```

`is_done=true` 却从来没有成功构建时间。增量更新 `search.Update()` 只看 `IsDone`，误以为索引已就绪；但 `search_nodes` 实际为 0，搜索自然什么都搜不到。

处理：

- [internal/bootstrap/index.go](../internal/bootstrap/index.go) 的 `InitIndex()`：不再无条件把进度置为完成。只有 `IsDone && LastDoneTime != nil && Error == ""` 才算真正完成；发现伪完成则回写 `IsDone=false` 并告警。
- [internal/search/build.go](../internal/search/build.go) 的 `Update()`：完成判断加上 `LastDoneTime != nil`。
- [server/handles/index.go](../server/handles/index.go)：`UpdateIndex` 开始时写 `IsDone=false`（保留上次成功时间与错误），失败分支同样写 `IsDone=false`；`ClearIndex` 清空后写 `IsDone=false` 而非 `true`；`BuildIndex` 的 quit 分支在 `eMsg != ""` 时也写未完成。

**② 差异比对只比文件名，漏掉同名覆盖**

[internal/search/build.go](../internal/search/build.go) 原先把当前对象和索引节点各构造成「名字集合」，只做 `Difference`。同名文件大小变了（覆盖写入）不会被识别，搜索结果一直是旧的。改为用 `名字 + 是否目录 + 大小` 三元组比对，并相应调整删除/新增的去重逻辑（避免同名多节点残留）。

**③ `DisableIndex` 检查不一致**

全量构建会跳过 `DisableIndex` 的存储，增量更新却没有，导致这类存储被用户浏览时仍写进索引。新增 `isDisabledIndex()`，`Update()` 与 `UpdateForced()` 都遵守。

**④ 搜索实例未就绪时 panic**

[internal/search/search.go](../internal/search/search.go)：`Search()` 原先直接 `instance.Search()`，`search_index=none` 或初始化失败时会 nil 解引用崩溃。加了 nil 保护，返回明确错误；并导出 `Enabled()` 供 watcher 判断。

### 2. 新增 `indexwatch` 模块：按驱动/按目录主动维护索引

**设计前提（与用户确认过）**：`139Yun` 等网盘没有变更推送能力，无法做到真正的事件实时，只能轮询；`Local` 可以靠操作系统文件事件做到近乎实时。因此按驱动分两种模式，且默认全部关闭、只作用于用户显式配置的少量目录，不做全局递归。

新增目录 [internal/indexwatch/](../internal/indexwatch/)：

- [watcher.go](../internal/indexwatch/watcher.go)：规则模型、加载/重载、调度与通用扫描。
- [local_fsnotify.go](../internal/indexwatch/local_fsnotify.go)：Local 的 fsnotify 事件监听。
- [watcher_test.go](../internal/indexwatch/watcher_test.go)：规则解析、路径映射测试（跨平台，CI 覆盖 Windows/Ubuntu）。

**规则来源**：设置项 `index_watch_rules`（JSON 数组）+ 总开关 `index_watch_enable`，在设置页可直接编辑、改完即生效（通过 setting hook 重载，无需重启）。单条规则字段：

| 字段 | 含义 |
|------|------|
| `enabled` | 是否启用该规则 |
| `driver` | `139Yun` / `Local` / `Crypt`，留空不限（大小写归一化） |
| `path` | OpenList 挂载虚拟路径 |
| `interval` | 轮询间隔秒数（默认 60） |
| `depth` | 递归深度，`0` 表示只看当前目录 |

配置示例：

```json
[{"enabled":true,"driver":"139Yun","path":"/移动云盘/追剧","interval":600,"depth":2}]
```

**两种扫描模式**：

| 模式 | 适用驱动 | 机制 |
|------|----------|------|
| `local` | `Local` | fsnotify 监听真实目录，事件 500ms 防抖后只更新受影响的父目录，近乎实时 |
| `poll` | `139Yun`、`Crypt` | 按 `interval` 定时递归扫描到 `depth`，逐目录更新索引 |

- `Crypt` 是虚拟加密层，底层事件拿到的是密文路径，映射回明文需要完整 nameMap、容易出错，因此统一走定时扫描，由 OpenList 自己解密成明文路径后再更新索引。
- 扫描列目录一律用 `Refresh:true + SkipHook:true`，绕开缓存、且不触发普通的 ObjsUpdateHook 造成重复更新。
- 更新索引走新增的 `search.UpdateForced()`：按路径强制维护，绕过全局 `auto_update_index` 开关和进度门槛，但仍遵守 `ignore_paths` 与 `DisableIndex`；全量构建期间跳过（构建会重扫整棵树）。

**针对用户规模的流量控制**：

- 每条规则独立互斥锁，上一轮没跑完就跳过本轮，避免叠加；
- 全局并发闸门（同时最多 2 个扫描），防止多条规则打爆网盘 API 与 SQLite；
- 失败指数退避（1x→2x→4x→8x，上限 30 分钟），避免被网盘风控；
- `depth` 限制递归层数，用户按 4 个父目录 + 两级子目录配置即可覆盖其结构。

**启动与热重载**：通过 [cmd/root.go](../cmd/root.go) blank import 引入；包 `init()` 中等待 `conf.StoragesLoadSignal()`（存储加载完成后）再启动；设置项变更即时重载规则。

### 3. 依赖：`fsnotify`（经用户提供的 socks5 代理下载）

用户明确要求 Local 用真·文件系统事件而非轮询快照。本机 `go.mod` 原本没有该依赖，且默认网络无法访问 `proxy.golang.org` / `sum.golang.org`。按用户提供的 `socks5://127.0.0.1:10808` 代理下载并写入依赖：

- [go.mod](../go.mod) / [go.sum](../go.sum)：`github.com/fsnotify/fsnotify v1.7.0`（校验和经 sumdb 校验）。
- 其依赖的 `golang.org/x/sys` 项目已有更高版本，无需额外变更。
